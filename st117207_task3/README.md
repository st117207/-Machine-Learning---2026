Выполнил: студент группы st117207 Белобородов Д. А.

Снижение размерности и кластеризация многоканальных измерений
гидравлического испытательного стенда (набор UCI Condition Monitoring of
Hydraulic Systems, DOI 10.24432/C5CW21). Из семи каналов PS1–PS3, FS1, TS1,
EPS1, VS1 за каждый из 2 205 циклов вычислены среднее, СКО, минимум и
максимум — матрица 2 205 × 28. Сравниваются PCA с центрированием и со
стандартизацией, факторный анализ на 2, 3 и 5 факторов, а также KMeans,
иерархическая кластеризация Уорда и DBSCAN на одной подвыборке и одних и тех
же главных координатах. Метки состояний узлов в признаки не входят и
используются только для послетаковой проверки.

## Сборка одной командой

```bash
pip install -r requirements.txt
python build.py             # данные → модели → report.pdf (в корне проекта)
python build.py tables      # пересобрать таблицы и макросы без переобучения
python build.py download    # скачать и распаковать исходные каналы UCI
python build.py features    # пересчитать агрегаты из исходных каналов
python build.py clean       # удалить производные файлы
```

Сборка требует:

* Python 3.11+ и пакеты из `requirements.txt`;
* LaTeX с `pdflatex` (MiKTeX или TeX Live) — компиляция отчёта по
  ГОСТ 7.32-2017;
* интернет — только для `python build.py download`; в поставке проекта
  таблица агрегатов уже лежит в `data/raw/`, поэтому обычная сборка работает
  без сети.

Сырые каналы UCI (≈325 МБ) в архив не входят. Команда
`python build.py download` скачивает официальный архив, проверяет SHA-256
(`24128aad…af1f2`) и распаковывает семь используемых каналов; после этого
`python build.py features` пересчитывает `data/raw/hydraulic_aggregates.csv`
из исходных сигналов тем же кодом, что использовался при подготовке архива.

## Методика (кратко)

* **Данные** — 2 205 циклов, 7 каналов, 28 циклопризнаков. Пропусков и
  полных дубликатов нет. Признаки `PS2_min`, `PS3_min` (константы) и
  `FS1_min` (почти константа) исключены из анализа: после стандартизации они
  дают деление на ноль или вырожденную ковариацию. В работе 25 признаков, в
  аудите описаны все 28.
* **Разбиение** — хронологическое 70/30 по номерам циклов (обучение 1 544,
  тест 661). Дополнительно блочное: блоки по 50 циклов целиком делятся
  70/30. Все преобразования оцениваются только на обучении.
* **PCA** — два варианта предобработки (стандартизация и только
  центрирование), k = 1…10; ошибка восстановления `inverse_transform` на
  отложенных циклах в исходных единицах и относительно СКО признака.
* **Факторный анализ** — 25 стандартизованных признаков, 2/3/5 факторов,
  метод максимального правдоподобия, без вращения; нагрузки,
  `noise_variance_`, общности, лог-правдоподобие на трёх разбиениях.
* **Кластеризация** — одна подвыборка 1 200 циклов (54,4 % кампании,
  `random_state=42`) и одни и те же PC1–PC4 (89,1 % дисперсии), z-масштаб по
  обучению. KMeans (`n_init=20`), Ward, DBSCAN (`min_samples=10`,
  `eps=0,6` по k-distance). k = 2…6, силуэт, индекс Дэвиса–Болдина,
  устойчивость по 20 бутстрэп-подвыборкам (ARI).
* **Правило выбора k** объявлено до проверки меток: устойчивость ≥ 0,90,
  каждая группа ≥ 5 % объектов, затем наименьшее k с силуэтом ≥ 95 % от
  максимума среди допустимых. Выбрано k = 3.
* **Метки** используются только после фиксации разбиений: ARI/NMI с
  состояниями охладителя, клапана, насоса и гидроаккумулятора, матрицы
  сопряжённости, доли уровней по третям кампании.

## Основные результаты

* Главная ось вариации смешанная: температура, вибрация и мощность входят в
  неё одновременно, а счёт по PC1 сильно коррелирует с номером цикла
  (Пирсон −0,774, Спирмен −0,869). Чисто тепловой её считать нельзя.
* Устойчивая структура — деление кампании на блоки, совпадающие с заменой
  охладителя, плюс подобласть повышенного давления в раннем блоке
  (240 циклов, 212–702) и переходный неустановившийся участок, который
  отделяет DBSCAN.
* Состояния клапана, насоса и гидроаккумулятора собственных групп не
  образуют: ARI не выше 0,096, доли уровней клапана одинаковы по третям.
* Высокий силуэт без z-масштабирования и «почти двумерность»
  центрированной PCA — артефакты масштаба, а не лучшие разбиения.
* Все числа в отчёте подставляются макросами из `results.json`; вручную
  числа не редактируются.
